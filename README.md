# The hidden cost of menopause — landing page

Handoff notes for whoever continues this work. Everything here reflects the state of the `bruno/updates` branch at the time of writing; `main` still has the original page.

- **Live site:** https://menopause-campaign.vercel.app/
- **Design source:** Figma file "B2B Campaigns" — https://www.figma.com/design/2RfmlnlEy3BjXeBntYMkIa/B2B-Campaigns (page "↪ Landing Page")
- **What it is:** a single-page B2B campaign landing page for Sword Women's Health, built from the desktop Figma design and made responsive for tablet and mobile.

## Stack

Plain HTML, CSS and JavaScript. No framework, no build step, no dependencies.

| File | What it holds |
|---|---|
| `index.html` | All markup and copy (one page). |
| `styles.css` | All styles. Mobile-first; breakpoints at 640, 760 and 1024px. |
| `head.js` | The few lines that must run before the page is drawn (classes for the intro and the fade-ins, and the safety nets if `script.js` fails). |
| `script.js` | All behaviour (see "Interactions" below). |
| `vercel.json` | Security headers for every response (see "Deployment"). |
| `.vercelignore` | Files kept out of the deployed site (this README, `.claude/`). |
| `favicon.ico`, `assets/favicon.svg`, `assets/apple-touch-icon.png` | Icons, made from the Sword mark in `assets/logo-color.svg`. |
| `assets/` | Images and icons exported from Figma, plus self-hosted fonts in `assets/fonts/`. |

To work on it, open `index.html` in a browser. A local server is nicer (fonts preload cleanly), for example:

```bash
python3 -m http.server 8080
```

## Deployment

Vercel is connected to this GitHub repository. Every push to `main` deploys to production automatically; there is no build command and no output directory (framework preset "Other", root `./`).

`vercel.json` sends security headers with every response: a Content Security Policy (scripts, styles, images, fonts and media from this site only, and form requests to `api.hsforms.com` only; the page cannot be framed), X-Frame-Options, X-Content-Type-Options, Referrer-Policy and Permissions-Policy. Because of the policy, the page has no inline scripts or inline event handlers: the early script is `head.js`. Inline `style` attributes are allowed (the textures and the slider use them). If the page ever needs another outside service (analytics, a video host, a font service), add its address to the matching line of the policy, or the browser will block it.

If the repository is transferred to another GitHub account, the Vercel project's Git connection will need to be re-linked (or the project re-imported at vercel.com/new) before pushes deploy again.

**Share previews.** The `og:` and `twitter:` tags in `<head>` give LinkedIn, Slack, iMessage, X and WhatsApp a title, a description and an image: `assets/share-image.jpg` (1200 × 640, from the design). The image needs a full address, so it points at `https://menopause-campaign.vercel.app/`, the address `main` deploys to; Vercel keeps that address working once a custom domain is added. When the final address is known, change it in `og:image` and `twitter:image`, and add `og:url` and a canonical link with it. Share previews are cached by each platform: after a change, LinkedIn's Post Inspector and Facebook's Sharing Debugger fetch the page again.

## Page structure

Restructured on branch `bruno/updates` from the Figma frame "lp-lg v2" in the section "Receipt > Card Experiment". Sections in order, with the class to search for:

1. Navbar — `.site-header` (fixed, always on top)
2. Hero: the end of the receipt hangs down from the top, the copy is centred under it in the lower half — `.hero`, receipt in `.hero__stage`
3. Meet Sarah + her receipt (torn in half, `.halves`), then "The problem" stats and a collage of other people's receipts — `.sarah`, receipt is `.receipt`, collage is `.collage`
4. Cost of menopause calculator, with "See how it works for your population" and a Book a demo button under the results — `.calc`
5. One intake, one care team, one record: copy on the left, the app on a phone (Sarah's chat with her care team) on the right, with the texture behind it, not clipped to the section — `.connected`, the phone is `.phone`
6. Meet Sword Women's Health: one wide panel, copy and two points on the left; on the right the app on three phones, fanned out, and the Bloom pod — `.meet`, `.meet__card`, `.fan`
7. What changes when someone connects the dots (four stats) — `.outcomes`
8. The women behind the claims: a side-to-side carousel (a quote beside the member video, then two quotes on their own) — `.voices`
9. Whitepaper feature with page preview — `.whitepaper` (anchor `#download`)
10. Everything in one place (two resource cards) — `.resources`
11. FAQ — `.faq`
12. Closing CTA — `.closing`
13. Footer — `.footer`

**Design tokens.** The top of `styles.css` holds the page's design tokens as CSS variables, with the same names and 1440px values as the Figma variables (collection "Menopause LP") and text styles ("Menopause LP/..."). Change a value in both places together.

- **Type:** `--display-2xl` to `--display-xs` (Lora: 80, 64, 56, 40, 28, 20), `--body-l` to `--body-xs` (Figtree: 18, 16, 14, 12), `--label-m` (button labels: 15, SemiBold capitals) and `--label-s` (eyebrows: 12, capitals with 5% tracking). The larger display sizes are clamps that shrink on small screens; the top value is the design's.
- **Spacing:** `--layout-*` places sections (page margin 20, panel gap 20, content inset 80, section gap 120, section gap after "Meet Sword Women's Health" 180, column gap 24), `--stack-*` is vertical rhythm inside a section (48, 32, 24, 16, 8) and `--inset-*` is padding (panel 40, card 32, row 24, and `--inset-feature`, 64 at 1440, inside the three big cards: calculator, Meet and whitepaper). Gaps and paddings on the page use these tokens; the exceptions are the pinned section 2, the hero and the name chip beside "Meet". On phones (under 640px) `--inset-panel`, `--inset-card` and `--inset-feature` all drop to 20px, the page margin.
- **Radius:** `--radius-control` 8 (FAQ rows), `--radius-panel` 16, `--radius-feature` 32.
- **Greys:** `--grey-700` (#5e5e5e) is the grey for secondary text (notes, captions, bylines, labels): 4.5:1 or better on every background on the page. `--grey-600` (#808080) is for lines and fills only; as text it fails contrast at small sizes. Add `--grey-700` to the Figma variables too.
- **Buttons:** one `.btn` (padding 16/20, 4px corners, no border), in two looks. The default is Figma's Button/Primary: black, 43px high with a 15px label; on hover it goes pure black and grows 2px all round (a ring of its own colour, so nothing around it moves). `.btn--secondary` is Button/Secondary: frosted off-white, 42px high with a 14px label; on hover it goes solid and an arrow (`assets/ic-arrow-right.svg`) slides in after the label, on links only. The arrow takes 22px; the button's right margin gives that back, so it grows to the right and nothing beside it moves. The hover looks are for pointers that can hover; keyboard focus gets the arrow too. As in Figma, every "Download the guide" button is Primary; the resource cards' buttons, "Book a demo" in the closing section, "Learn more about Bloom" in the Meet card and the dialog's Close are Secondary. Phones (under 640px) get a smaller logo (81 × 20) and a smaller button in the header, both 8px inside the hero's top corners. The whitepaper's arrows (`.wp-carousel__btn`) are Figma's "carousel controls": the Secondary look on 36px circles.
- **Kept outside the tokens:** the receipts, the phone and the calculator keep their own sizes; `--edge`, `--gutter` and `--inset` are layout helpers derived from the tokens.

The desktop design width is 1440px, with a 20px page margin on all four sides; the wide panels (hero, section 2, "One intake", closing) are 1400px wide. **Side edges.** Everything that sits on the page keeps to one line, 100px in at 1440 (`--inset` plus the page's own 10px; 1240px of content): the navbar's logo and button, the content of section 2, every section's heading and content, the big cards' outer edges and the footer. `--gutter`, the wide panels' inner padding, is `--inset` for that reason. Inside the three big cards the content is `--inset-feature` further in (64px at 1440, so 164px from the screen), and the copy of "One intake", which has no card, keeps to that same inner line. The line moves in with the screen: 86 and 143 at 1280, 60 and 106 at 1024. On tablets, content on the page is 33px in and content on a coloured surface 40px (the surface's own 20px plus 20px inside it); on phones 20px and 40px. Sections are separated by `--layout-section-gap` (120px on desktop) down to "Meet Sword Women's Health", and by the roomier `--layout-section-gap-lg` (180px) after it. The footer has 20px under it.

**Phones and tablets.** Three ranges: phones (under 640px), tablets (640 to 1023px) and desktop (1024px and up).

- **Frame:** on phones everything lines up on the 20px page margin: panels and cards start 20px from the screen edge and are padded 20px inside; headings outside a card start at the margin too. `--inset` grows from there to the desktop's 100px as the screen widens.
- **One column below 1024px:** Sarah's story and her receipt, "One intake" (copy, then the phone), the calculator (inputs, then results) and the whitepaper (text, pages, then the arrows and the button) stack. Meet Sword Women's Health stacks too, with its two points side by side on tablets.
- **Hero:** below 1024px the receipt is nearly as wide as the screen and would run under the logo and the button, so `.hero__window` fades it out before it reaches them. The headline shrinks with the screen on narrow phones so it stays three lines.
- **Receipts:** the tear and the travel into the collage need the pinned panel, so they are desktop only; the crumple plays everywhere (see below).

## Interactions

All of these live in `script.js`; the matching styles are commented in `styles.css`.

- **Hero:** fills the screen; the scroll indicator (`.scroll-cue`) sits at the bottom centre and links to section 2.
- **Section 2, two moments:** on desktop (1024px wide, 720px tall or more, and wider than tall, the same media query in `styles.css` and `script.js`) `.sarah-track` is a tall wrapper and the `.sarah` panel sticks under the navbar. Scrolling moves in steps through the hero and the two moments: one swipe (wheel, trackpad, arrow/page keys or a touch swipe) glides from the hero to moment 1 and from moment 1 to moment 2, and back the same way, up to the top of the page. From moment 2 on the page scrolls normally: nothing snaps on the way out, and coming back up it only catches on moment 2. The rest of that swipe, including trackpad momentum, is ignored; a new swipe is recognised straight away (a pause in the wheel events, or a sudden jump in their size), and a swipe made mid-glide is remembered and taken when the glide ends. If scrolling stops between two steps (for example after dragging the scrollbar) it glides to the nearer one, but not while a mouse button is still held down. Sideways swipes and pinch zoom are left alone, keys pressed with Alt, Ctrl or Cmd keep their normal meaning, and Space on a focused button still presses it. A resize or a reload part of the way through keeps the page on the step it was on, and a reload at or past moment 2 does not replay the tear. `MOMENT_2_AT` in `script.js` sets where moment 2 rests, `--pin-length` in `styles.css` how much scrolling the pinned stretch takes. Smaller screens show both moments one after the other. The pinned layout needs `script.js`, so its CSS only applies under the `js` class (set in `<head>`).
- **Receipts (hero and section 2):** the paper is meant to look hand-made, so everything the receipts do runs in stop-motion (6 frames a second), and once a second every receipt shifts a hair and its creases flip. Text and the card in section 3 stay smooth. Every number behind this lives in `RECEIPT_SETTINGS` at the top of the receipts code in `script.js`.
  - *Controls panel:* open the page with `?controls` in the address (for example `http://localhost:8080/?controls`) for a panel that changes those settings live, replays the intro, the tear and the crumple, and copies the current values so they can be pasted back into `RECEIPT_SETTINGS`. It is a design tool: without `?controls` it is never built.
  - *Uneven sides:* the paper is one picture stretched over each receipt, so its long sides would be ruler-straight. `roughEdges` in `script.js` clips every sheet (`.receipt__sheet`) to a shape whose sides stray inwards a little, as if cut by hand: a long bow plus two finer wanders, different for each receipt and each side, the same for the two halves of a torn one. `edgeRough` scales it (0 = straight). The outline stays put when the creases flip.
  - *Intro (hero):* as the page opens, five things happen in order. (1) The hero's background fades in (the `intro-pre` class, set by `head.js`, hides it until `script.js` lets it go). (2) The title, "The hidden costs of menopause" (`.intro-title` in `.hero__stage`, decorative and hidden from assistive technology; the page's `h1` is still the headline), appears a word at a time (`titleDelay`, `titleStagger`, and `titleLastStagger` for the longer pause before "menopause"): each word simply switches on, with no fade. On desktop it sits either side of where the receipt will be, "The hidden / costs" on the left and "of / menopause" one line lower on the right; on phones and tablets it is two centred lines just above the paper. (3) After `titleHold` the receipt (Sarah's, without her details; `script.js` copies it into `.hero__slot`) appears on a roll in the middle of the hero, 459px wide where there is room (`INTRO_W`), and unrolls down past the bottom edge, slowly at first and then faster (`unrollEase`) (`--paper-start` in `styles.css` is where its top starts). (4) The paper feeds upward like a till printer, coming down to its resting width (371px, `.hero__slot`) on the way, and the title rides up and out of the hero with it, until only the receipt's end hangs down from the top (`--end` in `styles.css` sets how far down; the copy starts just under it). (5) The navbar, the hero copy and the scroll cue, held back by the `intro-hold` class (also set by `head.js`), fade in near the end (`introTextAt`), once the paper has cleared them. It plays once per visit; scrolling on cuts it short, and opening the page part of the way down, or with "reduce motion", skips it. A small, faint round button in the bottom left corner of the hero (`.intro-replay`, added by `script.js`) plays it again from the start. `head.js` also sets two safety timers: if `script.js` never takes over, or stops part of the way through, the page shows everything as a plain page after 4 seconds (no intro, no fade-ins, nothing pinned).
  - *Tear (hero to moment 1, desktop):* gliding from the hero to moment 1, that receipt tears in half and the halves come to rest side by side (`.halves`, built by `makeHalves`; `HALVES` holds the geometry). The tear runs along the gap between two visits, the one nearest the middle, so no print is cut (`layoutHalves` works it out and gives both halves the same ragged edge). From the first frame the strip comes down with the page until the tear line is in the middle of the screen (`tearTravel`). Then, in `tearSeconds` (1.3s): the strip is tugged (it tilts a little, eases back and tilts again); the tear starts at the right edge and runs across to the left, not evenly (it goes with a jerk, catches about a third of the way, then gives all at once), with the halves swinging open behind it, shivering while the paper is under strain; and the halves fly to their places side by side, the top one first, each on a slight arc, overshooting a touch and rocking before they settle. The torn edge itself is uneven on purpose: a slow wander, a shorter ripple, a fine fray and a few snags (`EDGE`). The tear has its own frame rate (`tearFps`, 10 against the paper's 6), so its uneven pace shows. While it tears it keeps its own course across the screen, whatever the page is scrolling underneath. It only plays forwards: the two halves stay in section 2, and going back up the hero simply has its receipt again (and tears again on the next way down).
  - *Collage (moment 2, desktop):* the two halves shrink into `.collage` and the other receipts deal out from behind them. The other receipts are copies of hers filled in from `OTHER_RECEIPTS` in `script.js` (invented people and claims, illustrative, too small to read); each entry's `slot` places it in the collage.
  - *Crumple (leaving moment 2):* on desktop, as soon as the page scrolls about 110px past moment 2 (`crumpleAfter`) (on phones and tablets, once the middle of the collage has scrolled up into the top third of the screen), every receipt is swapped for three pictures of itself crumpled (folded, scrunched, ball). `paintCrumple` paints them on canvases, pixel by pixel: the sheet is broken into irregular facets, each lit from the top left and carrying the receipt's print at its own angle. Their look is set by the `ball…` values in `RECEIPT_SETTINGS`, and the controls panel shows a live preview. The crumpled receipt then hops and falls off the bottom of the screen. From its first crumpled drawing each receipt is in `.fall-layer`, a layer fixed over the whole screen, placed where the pile was when the receipts let go: the crumpling stays put on screen however fast the page scrolls on, the panel's edge doesn't clip it and it passes in front of the next section. It plays on its own clock while the page keeps scrolling. Scrolling back to moment 2, the receipts pop back flat.
  - On phones and tablets the hero plays the same intro, the receipt in section 2 is simply shown in two halves and the collage is already dealt out; scrolling on, its receipts crumple and fall as they do on desktop, and pop back when the page returns. With "reduce motion" everything is static. Without `script.js` the hero has no receipt and section 2 shows the plain receipt through `.receipt-window`.
  - The receipt is sized in `--u` (1/371 of its width), so the same markup draws Sarah's and the small ones.
- **The phone and the chat ("One intake"):** `.phone` is the Marketing Kit's "Chat / Device" built in HTML, 300 × 633 (the kit's 270 × 570 phone; `--pw` is its width and every size inside is a multiple of `--pu`, one unit of the kit's phone; screens under 360px wide get a 260px phone). Its corners are a little less round than the kit's (36 units against 45). It shows Sarah's chat with her care team: the header (three photos, "Your Care Team"), the conversation (`.turn` is one person's turn, `.bubble` one message; the care team from the left, Sarah from the right, in lilac) and the reply field. The member's photo is Sarah's (`assets/avatar-sarah.webp`), not the kit's default face, so she is the same woman as in section 2. On desktop (1024px and up) the phone fades in first and then the messages arrive one by one (`WAITS` in `script.js` is the pause before each), each pushing the ones before it up, as in a chat; it plays once. Below 1024px, and with "reduce motion", the whole conversation is simply there.
- **The phone's journey (desktop, 1024px and up):** when the Meet card comes into view, the phone flies down to it in one movement (0.95s), whatever the page is doing meanwhile: it moves over the page, not with the scroll. It goes straight down, shrinking to the card's size from the middle of its top edge (`--fly-y` and `--fly-s`, measured by `script.js`), so it lands to the right of its place in the fan, by `--push`. There the flying phone is hidden and a copy of it that lives in the card (`.phone--twin` in `.fan__chat`, made by `script.js`, scaled by `--k`) takes over, because the copy can sit behind the other screens and the flying phone cannot. Then the other screens come in from the right and push it left into place, in two steps: the session pushes it half the way (`.is-step1`), the exercise pushes both the rest of the way (`.is-step2`), and the pod comes last (`.is-step3`); `styles.css` holds the movements. Scrolling back up to the first section undoes it: the screens leave and the phone flies back. When it goes: the two places rarely fit on the screen together, so it leaves at the point where as much of its place in the card is in view as is still in view of the phone itself; on a tall screen, where both fit, it waits until the phone has reached the top of the screen (`where()` in `script.js`). Turning round half way is safe: the movements are CSS transitions, which simply change course. Opening the page further down starts with the phone already in the card.
- **Meet card:** a card as wide as the sections below it (1240px at 1440). The background is `assets/meet-bg.jpg`. The visual is `.fan`: the chat phone again (the copy described above; without `script.js` its place stays empty), a guided session (`assets/app-session.webp`) and a pelvic floor exercise (`assets/app-exercise.webp`), both exported from the design at 3x with the phone's frame (the kit's rounder corners are cut into them; a white ground behind each fills them out to the chat phone's corners), and the Bloom pod (`assets/bloom-pod.webp`, the design's own picture, 505px wide). Everything in the fan is placed and sized in percent of the fan (479 × 516 in the design), so the pod always keeps its size next to the phones, whatever the screen. Below 1024px, and with "reduce motion", the three screens and the pod are simply there.
- **Section 3 texture:** `.connected .tex-bg` sits behind the page (`z-index: -1`) and is only cut off at the edges of the screen, so the blurred texture runs on above and below the section instead of stopping at a frame. It fades in once the section's top has come up to the middle of the screen, and out again if it goes back down (`.is-lit`, set by `script.js`; only with the page's fade-ins on).
- **Quotes (section 7):** `.voices__track` is a scroll-snapping row of three slides, so it can be swiped or scrolled sideways without any script. `script.js` adds the turns: the bar under the slide on show fills up over `--turn` (7s, in `styles.css`), then the row glides on to the next slide, and after the last one back to the first; a click on a bar goes straight to that slide, and the two small arrows after the bars (`.voices__arrow`: plain chevrons, no ground) go one slide back or forward, round and round. It waits while the pointer or the focus is on the carousel, while it is off screen, and while the video plays. With "reduce motion" nothing moves on by itself. On desktop every slide is at least 400px tall, on the page's content line like the heading above it (40px, left), and the bars sit at its bottom left, in the same place on every slide; the first slide has the quote (48px) beside the video, the other two have the quote (32px) on the left and who said it on the right, resting on one line.
- **Whitepaper carousel:** `.wp-carousel` is a scroll-snapping row of pages with arrows, a page counter and a slow autoplay (paused on hover or focus). Its four pages are the whitepaper's cover and pages 4, 5 and 13 (`assets/whitepaper-cover.webp` and `assets/whitepaper-page-*.webp`), made from the designer's 1546 × 2000 exports at two sizes, 683 and 1366 wide (`-2x`); the browser picks the one it needs.
- **Calculator:** built on the Excel model "Cost of menopause: Sword vs traditional cost". Client inputs (eligible lives, optional women counts, funding type) recalculate the headline numbers live (base case, with its low and high range). Three things differ from the Excel, after review: the cost per woman is $2,080 (the measured Bloom savings per member in the menopause program) and not the $3,250 visit list; the Sword fee is $750 for ASO and 10% less ($675) for fully insured, never more than $1,000 per member; and the cost always counts only the women who seek care. The assumptions (cost per woman, Sword fee, population shares, share who seek care, share who use Sword) are not shown on the page: they are the `CALCULATOR_ASSUMPTIONS` object in `script.js`. The formulas are in `calculate()` right below it, with the Excel cell each one stands for in a comment.
- **Download form:** every "Download the guide" button (`a[href="#download"]`) opens a pop-up, the `<dialog id="guide-form">` at the end of `index.html`. It is our own form, not HubSpot's embed: `script.js` posts it from the browser to `https://api.hsforms.com/submissions/v3/integration/submit/{portal}/{form}` for the HubSpot form "Download the report" (ids in `HUBSPOT_FORM`; they are public, the same ones as in HubSpot's embed snippet), and HubSpot then emails the download link. The fields (first name, last name, company, email, all required) are that form's; if the form changes in HubSpot, change them here too, because HubSpot rejects a submission that misses a required field and silently drops a field the form does not have. The wording is the page's own ("Work email", "Send it to my inbox", the privacy line), not the HubSpot form's; the privacy line shown is also the consent text sent with the submission (`consentText`), so change both together. The form's hidden fields (`utm_campaign`, `utm_content`, `utm_medium`, `utm_source`, `form_slug`) are filled from the page address when it carries them, as HubSpot's embed does. Consent is sent as the form is set up in HubSpot: legitimate interest, subscription type `3905884755`. A hidden honeypot field (`hp_note`) is the only spam check. To try the pop-up without sending anything, add `?hubspot=mock` to the address (the console shows what would be sent, then the thank-you appears) or `?hubspot=fail` (then the error appears). Both work only on localhost and on the preview (`menopause-campaign-preview…vercel.app`), never on the live site, so a shared link carrying them cannot silently drop real requests. It is drawn as one of the page's receipts (`.guide-form` in `styles.css`): the receipts' paper (`assets/receipt-paper.png`, shown at its natural proportions), sides cut a little unevenly (a fixed `clip-path`), a perforated end (a `mask`; `--bite` sets the size), a centred header with today's date over a rule, dashed lines to write on in place of boxes, and the receipts' barcode. It arrives in four frames, like the rest of the paper. While the form is open the page behind does not scroll. Without `<dialog>` support or without `script.js` the buttons simply jump to the whitepaper section.
- **Scroll fade-ins:** elements marked `data-reveal` fade in themselves; `data-reveal="children"` fades direct children in sequence.
- **Navbar:** transparent, with nothing behind the logo and the button: the page scrolls under them as it is.
- **FAQ:** native `<details>` elements, all closed by default; answers slide open and the circled plus becomes a circled minus.
- **Video frames:** add `data-video-src="<url>"` (and `data-video-title`, its name for screen readers) to a `.video` element. Its play button swaps the poster for an inline player and starts it with sound; the file only starts loading then. When the video ends, the poster and the play button come back. Without `data-video-src` the button does nothing.
- **Member video (section 7):** `assets/video-dollie.mp4` (1920 × 1080, 63 s, 32 MB, subtitles burned in), poster `assets/video-dollie-960.webp` and `assets/video-dollie-1600.webp` (16:9 WebP, 41 KB and 76 KB; the browser picks the size it needs). The frame is 16:9, the film's own shape, so its titles and subtitles are never cut off. While it plays the quotes carousel holds its turn; it pauses when its slide moves out of view or the carousel leaves the screen. The local preview server (`python3 -m http.server`) does not answer byte-range requests, so on localhost Safari will not play the video and Chrome cannot skip ahead to a part that has not loaded yet; Vercel answers them, so the deployed page is fine.
- **Reduced motion:** visitors with "reduce motion" enabled get no fade-ins, no carousel autoplay, and section 2 switches moments without the in-between. The setting is read live, so turning it on or off while the page is open takes effect straight away.
- **Print:** a print stylesheet at the end of `styles.css` shows every section as a plain page, with nothing fixed or floating over the content.
- **In-page links:** the page scrolls smoothly to in-page anchors (`html.smooth-ok`, set once the page has loaded so a link opened part of the way down jumps straight there), and `scroll-padding-top` keeps the target clear of the navbar.

The old hero/receipt scroll story (sticky receipt, 3D paper roll, living paper, flip) was removed in the restructure; the unroll came back in a simpler, stop-motion form (see "Receipts" above). The original is still on `main`.
